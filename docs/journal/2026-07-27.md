## 核心决策

- PostgreSQL 领域状态是唯一真相源。
- 外部 Agent 框架不得直接推进全局状态或创建正式 Artifact。
- MVP 必须具有 Native Adapter，并用统一 Task Contract 接入其他框架。
- LangGraph 与 Microsoft Agent Framework 进入图执行 POC。
- AgentScope 进入 Worker、权限、事件和沙箱 POC。
- OpenClaw/A2A Adapter 后置。
- ChatDev、MetaGPT、EvoAgentX、GEAR、GAIA、CAMEL 等主要作为产品和协议设计参考。
- P0 不实现自由 Swarm 和在线自演化。

## Grill Me 决策补充

- MVP 必须使用真实 LLM、并行 Agent、正式 Artifact 和代码执行完成验收。
- 内置自适应 Grill Me，形成 RequirementContract 和动态 OutputContract。
- Workflow 和 Agent 首次从零生成；生成器有版本化规范和最多 3 次自动修复。
- 成功运行可沉淀并共享场景包。
- “需求到开发”流程必须交付可运行、可测试 Demo，而不是只交付文档。
- 编码任务使用独立 Worktree 和沙箱，主工作区变更需用户批准。
- MVP 支持本地文档与带快照证据的网页搜索。
- 默认资源限制为 5 个并发 Agent、3 轮辩论、单节点 10 分钟、单 Run 60 分钟，并具有 Token/费用上限。
- 本地应用匿名访问公共场景市场；普通场景包声明式运行，可执行插件单独授权、隔离并记录操作日志。

## MiroFish 知识与图谱架构参考

- 数据库、知识图谱和知识库管理参考 MiroFish 的资料解析、Ontology、实体关系图谱、Persona 生成、运行记忆写回和 ReportAgent 检索链路。
- PostgreSQL 继续作为领域与版本真相源，不照搬 Zep Cloud 强绑定及 JSON/SQLite 多状态源。
- MVP 使用 PostgreSQL 关系表和向量接口表达图谱，Knowledge Graph Service 保持可替换，后续可接 Neo4j、Nebula、Zep 等后端。
- 运行行为先进入 Run Memory，经证据、冲突和审批后才能写入长期可信知识。
