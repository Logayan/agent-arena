# 2026-07-28 工作日志

## 已确认方向

用户确认江湖 Online 平台需要符合 Harness Engineering、Loop Engineering 和 Graph Engineering。

本次将三者从概念要求转成平台级、可实现和可验收的架构基线：

- Harness Engineering：执行身份、Prompt、上下文、工具、权限、模型、预算、工作区和沙箱被编译成不可变执行快照；
- Loop Engineering：长任务具有持久 Goal/Plan/Action/Observation/Evaluation/Revision/Checkpoint，支持停滞检测、恢复和明确终态；
- Graph Engineering：分别治理执行图、知识/社会图和生产溯源图，并具备 Schema、静态编译、版本、差异和权限化查询。

## 关键边界

1. 三类工程要求不改变“Workflow 与 Agent 从零生成”的产品原则；Graph Compiler 提供约束和诊断，不提供固定业务模板。
2. PostgreSQL 领域对象仍是正式真相源，图后端、Agent 框架和 Checkpoint 实现均可替换。
3. 可复现指输入、配置、环境、轨迹和差异可解释，不承诺真实 LLM 输出逐字一致。
4. Loop 的完成由 AcceptanceContract、OutputContract、Gate、独立 Judge 或用户决定，Agent 自称完成不构成正式完成。

## 已有 Agent 库场景补充

用户补充确认：平台已有多个 Agent 时，用户输入需求后可以从中选择 Agent 使用。

系统行为确定为：Workflow 仍按当前需求从零生成；本次 Agent 编队重新规划，但成员来源可以是已有 Agent、已有 Agent 的派生版本或针对能力缺口从零生成的新 Agent。平台自动推荐，用户可以指定、排除和替换。任何被选 Agent 都必须创建新的隔离 AgentInstance 和 Harness Snapshot，不能直接继承历史私有上下文。

## 拟人化行为原则补充

用户进一步确认：拟人 Agent 在协作、争辩和抗争中需要呈现不同表现，但底层出发思路一致。

本次将其解释并固化为“同源异态”模型：所有 Agent 都从身份、职责、目标、立场/利益、知识边界、关系、情境、制度和权限出发；不同 Agent 因这些配置与历史经历不同而形成不同关注点、证据门槛、质疑方式、妥协条件和表达风格。拟人化不得覆盖事实、权限、Policy 和安全规则，也不得通过展示模型私有思维链来证明。

## 长期操作型 Agent 与 OpenClaw 方向

用户认可将 OpenClaw 能力用于可以执行大量现实操作的拟人 Agent。

架构决策为：江湖 Online 继续掌握 Workflow、Harness、Loop、Agent 社会关系、Artifact、Evidence 和裁决；OpenClaw 作为长期操作型 Agent 的优先 POC Adapter，承接独立身份、渠道账号、Skills、浏览器、Shell、代码、文件、消息、邮件、日历、定时任务、沙箱和后台子 Agent。所有真实操作必须返回平台经过正式 Gate，外部 Session 或消息不能直接成为完成依据。

## Workflow 与 Agent 资产复用原则调整

用户确认 Workflow 和 Agent 都可以被保存和复用，只有没有适用资产时才新建。本次将此前“每次从零生成”调整为：

```text
检索已有资产
-> 完全适用则复用
-> 部分适用则创建派生版本
-> 无适用项才从零生成或新建
```

复用不能直接沿用历史 Run 状态或私有上下文。Workflow 必须重新绑定当前 Contract、知识、Agent、Policy 和预算并通过 Graph 编译；AgentBlueprint 可以复用，但每次 Run 必须创建新的 AgentInstance。系统记录候选资产、适用性、缺口和未采用原因。

## 大江湖与小江湖需求补充

用户指出 SRS v2.0 未清晰定义大小江湖。本次增加独立章节，明确：

- 大小江湖是某次 Run 或节点实际参与的 Agent 社会规模，不是 Agent Registry 资产总量；
- 小江湖是最小必要团队，是 MVP 默认，但仍允许必要的协作、红队和独立裁判；
- 大江湖增加认知差异、利益相关方、阵营、关系和互动方式，但不等于无限 Agent 或自由聊天；
- 江湖规模可作用于整个 Run、子图、单节点、返工轮次或对比实验；
- 支持 auto、small、large、custom 四种策略；
- 运行中切换规模属于结构性介入，必须版本化、重新校验和重跑受影响边界；
- 新增 `SR-JH-001~016` 和五个验收场景。

## OpenClaw 提升为 P0 多 Agent 运行框架

用户确认 OpenClaw Adapter 必须进入 P0，并可作为整体多 Agent 运行框架。本次调整为：

- OpenClaw Gateway + Adapter 是所有 P0 LLM Agent 节点的默认运行路径；
- OpenClaw 承接 Agent 身份装载、会话隔离、多 Agent 路由、并行、子 Agent、消息、工具和沙箱；
