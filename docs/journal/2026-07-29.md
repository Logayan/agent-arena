# 2026-07-29 工作日志

## 修正 Workflow 生成策略

用户指出原第 6.9 节标题错误地把新建路径表述成默认逻辑。详细设计第 6.9 节已调整为“Workflow 资产复用、派生优化、组合重构与新建”：

- 默认先检索项目、Registry、场景包和已安装市场 Workflow；
- 评估 Contract、Artifact、能力、知识、工具、权限、预算和环境适用性；
- 根据覆盖情况选择直接复用、派生优化、组合重构或创建新 Workflow；
- 从零创建仅用于没有适用资产或用户明确要求的情况；
- 优化不覆盖原版本，必须创建派生 WorkflowVersion；
- 组合复用记录子图来源，并处理 Schema、权限、职责和 Gate 冲突；
- 产物反向规划用于新建流程或补齐复用后的缺口。

## 明确 Workflow 本地保存与复用读取

用户进一步确认可复用 Workflow 必须说明保存位置和复用获取方式。详细设计新增：所有创建、安装、派生、冻结和运行过的 WorkflowVersion 必须本地持久化；PostgreSQL 保存正式元数据和结构投影，对象存储保存完整规范化 Definition，检索索引仅作可重建投影。市场 Workflow 必须安装、验签、固定版本并复制到本地后才能运行。补充 Workflow 保存字段、禁止保存的运行私有内容、复用读取时序及 `workflow_source_version`、`workflow_applicability`、`workflow_search_projection`、`workflow_dependency` 等表。

## 明确用户需求输入的预期场景

平台主入口确定为目标导向的自然语言对话。用户预期直接表达“我要开发 XXX 系统并交付可运行 Demo”，无需先说“我要做需求开发任务”或理解 Workflow。系统识别 goal_execution、process_delegation、workflow_authoring 和 run_intervention 四类输入，生成 IntentDraft 和理解预览，再进入 Grill Me、Workflow/Agent 检索与构建。“指定 Workflow/Agent/场景包”作为高级可选项，不作为首次使用前置条件。

上述入口判断经用户纠正后废止。新的确认模型是两类并列主场景：第一，用户描述“我要建立需求开发任务流程”，系统构建或复制优化 Workflow 与多 Agent，用户确认后保存资产，不创建 Run；第二，用户选择已有 Workflow，再输入“本次开发社区报修系统”等具体任务，完成任务级 Grill Me 后创建 Run。详细设计已同步修改核心时序、客户端双入口、GenerationJob 输入、数据表和 API。

## 明确 Workflow 固定绑定 Agent

用户确认 Workflow 资产应当已经绑定好 Agent。设计修正为：WorkflowVersion 冻结节点对应的 AgentBlueprintVersion、职责和关系；创建 Run 时不重新选择 Agent，只为固定 Blueprint 创建隔离 AgentInstance。运行时只有预先声明并校验的 fallback Blueprint 可以自动切换；用户主动替换 Agent 时必须创建派生 WorkflowVersion、重新编译并从受影响边界执行。
