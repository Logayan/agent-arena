## 9. 多 Agent 平台竞品调研

用户要求通过互联网了解友商和行业方案，重点参考：

- 阿里云开发者社区关于路由、委托、辩论、群体四种多 Agent 协作模式的文章。
- 阿里云百炼、Microsoft AutoGen、LangGraph、Google ADK、CrewAI、Amazon Bedrock、OpenAI Agents SDK 和 Dify 的官方资料。

主要结论：

1. 多 Agent 不等于多个角色共享聊天室，而是独立能力边界、明确移交、状态、产物、终止和评估的组合。
2. 主流方案都在融合确定性工作流与局部 Agent 自主性。
3. 路由、委托、辩论应作为 Agent Arena 的首批编排策略；群体协作后置。
4. Context Policy、Handoff 契约、运行持久化、人工介入、Trace、版本和评测必须作为平台核心能力。
5. Agent Arena 的差异化应放在 Agent 社会设计、协作对抗协议和持续评估，而不是单纯增加工作流节点。

## 10. 企业平台补充调研与目标蓝图

用户要求继续通过互联网研究，并重新整理用户需求和目标蓝图。

本轮新增研究：

- Microsoft Copilot Studio Connected Agents
- IBM watsonx Orchestrate
- Google Vertex AI Agent Engine 与 Agent Registry
- Salesforce Agentforce Builder、DX 和 Testing Center
- MiroFish、CAMEL、OASIS、MetaGPT
- MCP、A2A、NIST AI RMF 和 OWASP Agentic Security

新增结论：

1. Agent、工具、知识、工作流和评测必须成为可登记、版本化、发布和审计的组织资产。
2. 平台需要可视化与声明式双表达、确定性与自主性双运行语义。
3. MCP 作为 Agent 到工具边界，A2A 作为外部 Agent 协作边界。
4. 评测进入开发和发布流程，覆盖路由、工具、知识、结果、安全、成本和时延。
5. Agent Arena 在通用编排之上提供 Society、Policy、Debate、Evidence、Evaluation 和 Learning。
6. MiroFish 的社会关系、事件注入和深度交互可借鉴，但生产内核必须可控、可恢复、可验收。
