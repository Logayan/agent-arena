# ADR-0004：平台优先，课题案例仅作为验收

- 状态：已接受
- 日期：2026-07-24

## 背景

需求梳理过程中，曾将“课题最终演示选择哪个生产流”列为首要确认问题。

用户明确指出：

- 具体演示案例不是重点。
- 重点是 Agent Arena 整个平台。
- 最终从需求开发中选择一个具体需求完成演示即可。

## 决策

产品和技术实施采用“平台优先”原则：

1. 先实现 Workspace、Scenario、Knowledge Space、Agent Blueprint、Society Definition 和 Workflow Definition。
2. 再实现真实 Agent 运行、协作、对抗和评估。
3. 最后从需求开发中选择一个具体需求作为课题验收案例。

课题案例不得成为代码中的特殊分支，也不得决定核心领域模型。

## 验收案例的正确角色

验收案例用于验证：

- 平台能创建自定义场景。
- 平台能配置或生成 Agent。
- 平台能配置或生成工作流。
- 多 Agent 能真实协作和对抗。
- 平台能评价质量、成本和效率。

它不是：

- 平台首页固定数据
- 唯一工作流
- Agent 固定角色来源
- 核心架构边界

## 影响

- `/api/demo` 将来仅保留为示例模板或开发演示。
- 路线图先完成平台基础，再完成课题案例。
- 需求确认不再优先讨论具体案例内容。
- 当前“需求评审”文档保留为参考，不作为平台 P0 的定制规格。
