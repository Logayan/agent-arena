# ADR-0001：文档作为项目过程记录

- 状态：已接受
- 日期：2026-07-23

## 背景

用户要求项目中间输出、分析记录和后续实现过程均以文档形式保存在工作区，避免重要内容只存在于对话上下文。

## 决策

采用分层文档结构：

- `docs/01-research/`：外部框架和技术调研
- `docs/02-requirements/`：需求、范围和待确认事项
- `docs/03-decisions/`：Architecture Decision Records
- `docs/journal/`：按日期记录讨论、实施、验证和结果

代码开发阶段继续增加设计、测试和运维文档，并通过 `docs/README.md` 统一索引。

## 记录边界

保存对项目有用且可复核的内容，包括：

- 获取的事实和来源
- 关键分析依据
- 备选方案及取舍
- 已确认结论和未决问题
- 实施修改、验证方式和结果
- 风险、失败尝试和后续行动

不记录模型不可见的内部思维链。文档提供足够的依据，使项目参与者能够理解和复核结论。

## 影响

- 每个实质性阶段都需要同步更新文档。
- 需求或架构变化必须修改对应文档或新增 ADR。
- 文档和实现应在同一次变更中保持一致。
