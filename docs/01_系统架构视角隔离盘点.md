## 3. 架构决定

### 3.1 责任边界

```text
Claude Agent SDK
  ├─ 单次 Agent 模型回合
  ├─ SDK Session 初始化/持久/续接
  ├─ Tool Use/Result 协议
  └─ MCP Server 接入

jianghu_workspace 工具网关
  ├─ delivery 路径限制
  ├─ Schema 与工具白名单
  ├─ 凭据隔离命令环境
  └─ 文件/命令副作用回执

江湖 Online 控制面
  ├─ Run / Node / Task / Attempt / Team
  ├─ 两轮公开协作与综合
  ├─ Judge / gate / rework
  ├─ Memory 审核、版本、命名空间与回读
  ├─ pause / checkpoint / resume
  ├─ retry / recovery / lease / fencing / reconciliation
  └─ Event 与 Artifact authority

耐久层
  ├─ PostgreSQL（生产）或 SQLite/WAL（本地兼容）
  ├─ Run workspace / manifest
  ├─ Artifact 原始字节与 SHA-256
  └─ Claude Session 状态目录 + sessions.json 映射
```

不得把平台编排能力笼统归因于 SDK；也不得因 Runtime 名称为 `claude_code` 就把 attestation 中的 `model=gpt-5.6-sol` 改写成“底层模型已证明为 Claude”。

### 3.2 OpenClaw 当前与历史口径

- **当前生产路由：** OpenClaw 不承担观察窗内产品入口执行。
- **当前残余：** 仅见迁移 SQL、旧 API 路由别名、旧事件/UI 文案别名、错误兼容和主动负向探针。
- **历史能力：** attestation 声明 `experiments/openclaw_baseline/openclaw_runtime.py` 与契约测试在产品包外，但这两个文件原始字节不在 13 项 Registry 中。历史会话、工具、Memory、恢复行为不可独立审计。
- **裁决：** 可证明“当前路由切到 Claude 且短窗失败关闭”，不能证明“历史能力已逐项等价迁移并可安全退役”。

## 4. 假设

1. Source attestation 所列 13 项覆盖了其定义的生产 Runtime 与部署输入；本交付只对已登记字节复算，无法证明未登记仓库文件不存在。
2. `runtime.route.attested` 的 10 个入口代表平台声明的产品入口集合；长期生产流量仍需更长窗口证明。
3. SDK Session 存储在运行时 state root 的实现能够跨宿主恢复；当前没有执行事件证明这一点。
4. PostgreSQL 为生产配置、SQLite 为本地兼容的源码注释与连接分支真实对应部署；当前 Registry 没有数据库运行配置/迁移回执。
