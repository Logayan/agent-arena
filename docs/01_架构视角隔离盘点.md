## 2. 当时的架构决定

### 2.1 不把未知填成否定

当时无 OpenClaw 原始源码、配置、接口和事件样本。结论应为：

```text
OpenClaw historical baseline=unknown_at_isolated_cutoff
```

而不是“OpenClaw 没有某能力”。

### 2.2 四层责任边界

目标边界在隔离阶段即确定为：

1. Claude Agent SDK / bridge：单 Agent Session、Invocation、Tool protocol 和 hook；
2. 江湖 Online：Run、Node、Attempt、Role、公开协作、Judge、Memory 和恢复控制面；
3. Tool gateway：Schema、授权、凭据、幂等、副作用验证和补偿；
4. Durable stores：Event、Artifact、Memory、Checkpoint、Lease 和 Operation。

该边界是目标架构，不是 sequence 37 时已经完成的实现事实。

### 2.3 退役门禁

当前路由通过与 OpenClaw 退役必须拆分：

```text
current route=may pass with platform evidence
historical parity and retirement=remain blocked
```

## 4. 仍然成立的独立风险

即使使用当前 4,395-event 快照，以下风险仍成立：

- OpenClaw raw baseline 不可用；
- Runtime source 只有平台 attestation，原始字节不可独立源码审计；
- 无 explicit SDK Session/Invocation lifecycle；
- Tool 无 native SDK/Invocation/result digest linkage，授权样本全 allow；
- workspace files 不是 formal Artifact，Registry 为 0；
- 当前节点只有两 actor，不是五角色生产流；
- 无 Judge reject/rework/rejudge；
- Memory 只有 read/use，无 write roundtrip；
- 无 intentional pause/resume；
- recovery 无 SDK continuation、terminal reconciliation 和 Run convergence；
- `model=gpt-5.6-sol` 不能与 route attestation 合成端到端 Claude model execution proof。
