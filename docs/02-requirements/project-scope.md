# 项目范围与 Client 需求

平台名称：**Agent Arena（多智能体协演场）**

## 1. 项目目标

选定一个生产流，设计多个 Agent 在其中协作与对抗，并实现一套能够运行、观察、干预、复盘和评估该过程的完整系统。

系统不只包含后端 Agent 引擎，还必须提供类似 MiroFish 使用体验的可视化 Web Client。

## 2. 当前确认范围

- 多 Agent 运行与任务编排引擎
- 共享知识、长期记忆和证据追踪
- Agent 角色、能力、立场和工具权限
- 协作、质疑、红队攻击、返工和裁决协议
- 报告生成和 Agent 访谈
- 实时运行状态、时间线和日志
- 类 MiroFish 的可视化 Client
- 历史运行、结果比较和可复现实验
- 示例生产流及量化评估
- 全过程文档化

## 3. 建议的首个生产流

当前建议：

```text
产品需求分析
  -> 方案设计
  -> 红队质疑
  -> 方案修订
  -> 裁判验收
```

该方向适合作为第一个实践，因为它同时包含：

- 多专业角色协作
- 信息不完整与观点冲突
- 可显式设计的攻击面
- 清晰的返工闭环
- 可量化的质量评价

目前仍需确认具体业务场景、典型输入和最终交付物。

## 4. Client 五阶段

1. **资料与目标**：上传资料，定义生产任务、约束和验收标准。
2. **知识与角色**：查看知识图谱，配置 Agent 职责、能力、立场和工具。
3. **协作与对抗**：查看任务分配、消息、产物提交、红队攻击、返工与裁决。
4. **结果报告**：查看最终产物、评分、证据引用、冲突和决策链。
5. **深度交互**：与报告/裁判 Agent 对话，采访或调查任意 Agent。

## 5. Client 主要视图

### 5.1 图谱视图

- 领域实体与关系
- 任务依赖
- Agent 组织关系
- 证据来源和引用链
- 冲突事实和失效事实

### 5.2 双栏运行视图

- 左侧：运行时间线、协作消息、对抗事件和阶段性产物
- 右侧：Agent 状态、当前任务、工具调用和质量门禁

### 5.3 报告工作台

- 左侧：报告目录和正文
- 右侧：交互工具、Agent 选择和调查表单
- 支持边看报告边追问证据或采访相关 Agent

### 5.4 运行控制台

- 开始、暂停、继续和停止
- 注入外部事件
- 调整规则或资源限制
- 查看运行成本和错误

### 5.5 对抗面板

- 红队攻击点
- 质疑和反证
- 缺陷严重度
- 责任 Agent
- 修复状态
- 裁判结论

### 5.6 Agent 详情

- 角色目标和系统约束
- 能力和工具权限
- 私有记忆与共享记忆
- 当前上下文
- 输入、输出和工具调用
- Token、时间和成本消耗

### 5.7 评估与历史

- 最终质量
- 成本和耗时
- Agent 协作贡献
- 红队缺陷发现率
- 修复成功率
- 多次运行对比
- 配置和随机种子复现

## 6. 深度交互

Client 应支持：

- 与报告/裁判 Agent 对话
- 与单个 Agent 对话
- 批量采访多个 Agent
- 向选定 Agent 发送同一份问卷
- 对比多个 Agent 对同一问题的回答
- 追溯回答使用的证据和当时记忆
- 将用户意见注入下一轮协作

## 7. 初步技术方向

- Client：Vue 3、TypeScript、Vite
- API：REST，用于项目、配置、产物和历史数据
- 实时事件：优先评估 SSE，需要双向低延迟控制时使用 WebSocket
- 后端：待系统架构阶段确认
- 图谱与记忆：抽象接口，避免将核心业务绑定到单一云服务

Client 借鉴 MiroFish 的信息架构和工作方式，但不复制其品牌资产。

## 8. 待确认事项

- 首个生产流对应的具体业务场景
- 典型输入材料
- 最终产物格式
- Agent 数量和角色
- 对抗强度及终止条件
- 验收指标和成功基线
- 是否需要完全本地部署
- 可使用的模型、预算和数据安全要求
