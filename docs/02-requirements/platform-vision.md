# Agent Arena 平台愿景与课题边界

- 版本：0.1
- 日期：2026-07-24
- 状态：愿景草案

## 1. 原始课题目标

课题要求是：

> 选定一个生产流，设计多个 Agent 进行协作与对抗。

课题希望解决的不是单角色聊天，而是让多个角色围绕真实生产流程分工、交接、质疑、修订和验收。

图片中给出的典型方向包括：

- 需求到文档生产流
- 代码生成与评审生产流
- 数据分析生产流
- 安全与质量评审生产流
- 测试设计生产流

核心要求包括：

- 至少包含 3 个不同角色的 Agent。
- 每个 Agent 有明确职责和工具。
- Agent 之间有清晰的信息传递、依赖和协作链路。
- 至少设计一个对抗或相互验证场景。
- 最终输出完整生产流程，并且能够运行和演示。
- 不应只停留在提示词或设计文档。

建议成果包括：

- 多 Agent 协作系统 Demo
- Agent 角色说明和协作流程图
- 代码仓库 README
- 至少一个完整生产流示例
- 单 Agent 与多 Agent 的效果对比
- 对效率、成本、冲突、返工和人工介入的说明

## 2. 用户的长期目标

Agent Arena 不应只完成一个固定课题 Demo，而应成为：

> **面向组织场景的多 Agent 社会操作系统与工作流工厂。**

用户未来可以提交任意员工、研发、客户或运营场景，平台根据目标、知识、工具、风险和验收标准，构建出对应的：

- Agent 团队
- 组织关系
- 协作协议
- 对抗机制
- 工作流
- 知识与记忆空间
- 质量门禁
- 人工介入点
- 效果评估和持续学习机制

## 3. 北极星体验

用户输入：

```text
业务目标
+ 场景材料
+ 组织规则
+ 可用工具
+ 成本和时间预算
+ 风险偏好
+ 验收标准
```

Agent Arena 输出：

```text
场景理解
-> 推荐 Agent 角色与团队结构
-> 推荐知识空间和权限
-> 生成任务图与协作协议
-> 生成红队/质检/裁判机制
-> 用户确认
-> 运行并实时观察
-> 形成产物、证据、缺陷和评分
-> 将有效经验沉淀到知识库
```

最终目标不是“帮用户写一个提示词”，而是：

> 用户描述一个工作目标，平台生成一套可运行、可观察、可干预、可评估、可复用的多 Agent 组织。

## 4. 平台优先、案例验收策略

### 4.1 平台建设主线

目标：

- 支持多场景创建。
- 支持 Agent、知识、工具和规则配置。
- 支持平台根据目标自动推荐或生成工作流。
- 支持组织级知识、权限和长期记忆。
- 支持工作流模板和 Agent 蓝图库。
- 支持运行评估和策略优化。

### 4.2 课题案例验收

课题案例不驱动平台架构，也不需要现在优先确定。

在平台具备自定义场景和动态 Agent 能力后，从需求开发中选择一个具体需求，通过以下流程完成验收：

```text
创建需求开发场景
-> 连接知识
-> 配置或生成 Agent
-> 配置或生成工作流
-> 真实运行
-> 协作与对抗
-> 评估单 Agent 和多 Agent 差异
```

案例必须通过平台配置产生，不能写死在代码中。

## 5. 目标场景族

### 5.1 员工场景

- 招聘筛选与面试评议
- 新员工培训与答疑
- 绩效目标拆解和校准
- 制度咨询与合规检查
- 跨部门方案评审
- 内部知识问答和任务协助

### 5.2 开发场景

- 需求分析与架构设计
- 编码、测试、审查和修复
- 故障诊断与恢复
- 安全威胁建模和攻击验证
- 技术债识别和重构评审
- 发布风险与变更审批

### 5.3 客户场景

- 销售线索分析和方案生成
- 客户需求澄清
- 客诉分析和处置
- 客户成功与续约风险
- 服务质量审查
- 合同、交付和风险协同

### 5.4 运营与决策场景

- 内容生产和事实核验
- 营销方案和品牌红队
- 数据分析和结论审查
- 经营计划和预算挑战
- 舆情模拟和应对演练

## 6. 平台核心能力

### 6.1 场景建模

- 将自然语言目标转换为结构化场景。
- 提取参与者、对象、约束、风险和交付物。
- 识别需要协作和需要对抗的环节。

### 6.2 Agent 组织生成

- 从 Agent 蓝图库选择角色。
- 根据场景动态生成角色。
- 配置职责、目标、工具、权限、记忆和预算。
- 生成团队、上下级、协作和监督关系。

### 6.3 工作流生成

- 生成任务 DAG 或状态机。
- 定义并行、串行、返工和终止。
- 定义消息 Schema 和正式产物。
- 定义人类确认点。

### 6.4 知识与记忆

- 组织知识
- 领域知识
- 项目知识
- 运行证据
- Agent 私有记忆
- 跨运行方法和经验

### 6.5 对抗与治理

- 红队攻击
- 角色间交叉质疑
- 独立事实核验
- 规则校验
- 裁判和仲裁
- 风险豁免与人工审批

### 6.6 评估与学习

- 质量、成本和时间
- 证据覆盖率
- 缺陷发现与修复率
- Agent 贡献度
- 冲突解决效果
- 单 Agent 与多 Agent 对比
- 基于历史运行优化角色、提示词和流程

## 7. “效果好”的定义

平台不能仅以“Agent 都执行完成”为成功。

每个工作流必须具备：

- 明确的任务成功指标
- 确定性规则检查
- 基于量表的质量评分
- 对抗覆盖率
- 证据可追溯率
- 成本和时延上限
- 人工抽检或基准答案
- 单 Agent 基线
- 多次运行的稳定性统计

平台只有在结果质量、风险控制或人工效率上优于基线时，才能称为有效。

## 8. 非目标

近期不追求：

- 一次性自动解决所有行业和所有岗位。
- 无需模板和验证即可生成完美工作流。
- 让 Agent 绕过组织权限直接操作生产系统。
- 只依靠 LLM 自评判定效果。
- 用更多 Agent 数量代替清晰的职责和协议。

## 9. 产品原则

- **场景驱动，而不是 Agent 数量驱动。**
- **知识、权限和证据先于自由对话。**
- **协作和对抗都必须服务于质量目标。**
- **正式产物优先于聊天记录。**
- **每个自动化决定都应可追溯。**
- **任何工作流都必须能够被停止和人工接管。**
- **经验可以复用，但数据必须隔离。**
