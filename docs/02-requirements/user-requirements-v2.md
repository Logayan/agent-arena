# Agent Arena 用户需求基线 v2

- 版本：2.0
- 日期：2026-07-24
- 状态：待用户确认
- 继承：保留 v1 全部已确认需求，本版结合第二轮互联网调研重新组织并补充

## 1. 一句话需求

用户需要的不是一个固定多 Agent Demo，而是一套属于自己的平台：

> 输入组织中的业务目标、知识、工具、约束和验收标准，平台能够帮助用户设计、测试、运行、观察、评估并复用一套可治理的多 Agent 协作与对抗工作流。

## 2. 用户真正要获得的结果

### 2.1 近期结果

- 不修改代码即可创建新场景。
- 不修改代码即可创建和配置 Agent。
- 使用真实模型、知识和工具运行多 Agent。
- 清楚看到协作、委托、质疑、修订、裁判和人工介入。
- 用同一任务比较单 Agent 与多 Agent 的结果。
- 通过一个需求开发案例完成课题验收。

### 2.2 中期结果

- 建立自己的 Agent、知识、工具、社会和工作流资产库。
- 将有效的生产流保存为可复用模板。
- 在员工、研发、客户和运营场景中快速组建 Agent 团队。
- 用评测和历史数据选择合适的角色、模型和流程。

### 2.3 长期结果

- 形成组织级 Agent 控制平面和多 Agent 社会体系。
- 连接内部 Agent、第三方 Agent、MCP 工具和企业知识。
- 根据业务意图半自动生成经过治理的 Agent 组织和工作流。
- 通过持续评测形成可审计、可优化的组织智能。

## 3. 产品定位与边界

### 3.1 产品定位

> **Agent Arena 是面向组织生产场景的多 Agent 社会设计、协作对抗运行与持续评估平台。**

### 3.2 平台负责

- 将业务意图结构化为场景、任务、产物、风险和验收标准。
- 管理 Agent、知识、工具、模板、评测和版本。
- 设计 Agent 之间的组织关系、权责和协作协议。
- 编排确定性流程和局部自主协作。
- 管理上下文、权限、预算、运行状态和人工介入。
- 保存 Artifact、Evidence、Defect、Decision 和 Evaluation。
- 对比、复盘和沉淀有效方法。

### 3.3 平台暂不承诺

- 自动生成后无需人工检查即可安全执行所有生产任务。
- Agent 越多效果必然越好。
- 用一次演示证明平台适用于所有行业。
- 只靠 LLM 裁判替代确定性规则、事实证据和人工责任。
- 首版支持数百或数千 Agent 的开放社会仿真。

## 4. 目标用户与核心任务

| 用户 | 核心任务 | 首版优先级 |
| --- | --- | --- |

| 场景设计者 | 描述业务目标、资料、约束、风险和验收 | P0 |
| Agent/流程设计者 | 创建 Agent、社会关系、工作流和协议 | P0 |

| 知识管理员 | 管理来源、版本、权限、有效期和经验写回 | P1 |
| 业务使用者 | 提交任务、接收产物、追问并给出反馈 | P1 |

## 5. 北极星用户旅程

```text
表达业务意图
-> 建立场景与验收契约
-> 连接知识、工具和外部 Agent
-> 平台推荐 Agent 团队、社会关系与工作流
-> 用户调整并通过静态检查
-> 生成测试与评测方案
-> 在安全环境试运行
-> 发布版本
-> 实时运行与人工介入
-> 查看产物、证据、缺陷和决策
-> 与单 Agent/历史版本比较
-> 批准模板和经验沉淀
```

## 6. 十个需求域

### 6.1 Workspace 与组织治理

- 创建 Workspace，隔离成员、知识、Agent、工具、模板和运行。
- 配置 Owner、Builder、Operator、Reviewer、Viewer 等角色。
- 每项资产有所有者、状态、版本、权限和审计记录。
- 密钥与用户数据只在受控服务端保存。
- 支持停用、撤销和隔离已发布 Agent 或工具。

### 6.2 Scenario Builder

- 用自然语言、表单和文件创建场景。
- 场景包含目标、背景、参与者、输入、约束、风险、预算、交付物和验收标准。
- 平台识别需要协作、对抗、人工判断和高风险操作的环节。
- 场景可复制、版本化、归档并生成测试集。
- 具体需求开发案例是场景实例，不是平台内置逻辑。

### 6.3 Knowledge Hub

- 创建组织、领域、项目、运行和 Agent 私有知识空间。
- 支持文档、代码、API 和后续企业数据源。
- 保存来源、版本、时间、权限、密级、置信度和引用位置。
- 支持关键词、向量及后续关系图检索。
- 支持检索调试和证据可视化。
- 运行经验写回前经过证据检查、冲突检查和审批。

### 6.4 Agent Registry

- 创建、编辑、复制、测试、发布、停用和版本化 Agent Blueprint。
- 配置身份、职责、目标、能力、模型、Prompt、工具、知识、记忆和预算。
- 配置结构化输入输出、Handoff 条件和上下文策略。
- 每个发布版本拥有能力描述、所有者、Endpoint 和评测结果。
- 支持本地 Agent、外部 A2A Agent 和 Agent-as-tool。
- 同时支持可视化编辑与声明式 JSON/YAML 导入导出。

### 6.5 Tool Registry

- 注册本地工具、HTTP API 和 MCP Server。
- 保存能力、参数 Schema、风险等级、凭据方式和调用范围。
- 工具授权到 Workspace、Agent、Scenario 和 Run。
- 高风险或不可逆调用必须支持人工审批。
- 记录工具输入摘要、输出摘要、时延、成本、错误和重试。

### 6.6 Society Designer

- 将 Agent 组织为团队、部门和层级。
- 定义协作、汇报、委托、审查、挑战、仲裁、观察关系。
- 定义谁可创建、修改、评审、批准和发布产物。
- 支持 Supervisor、专家组、红蓝对抗、委员会等模板。
- 同一 Agent 不得同时拥有提案、修改和最终批准的全部权力。
- 后续根据历史任务形成能力画像和声誉，但声誉不能突破权限。

### 6.7 Workflow Studio

- 同时支持顺序、并行、条件、循环、人工节点和子工作流。
- 支持路由、委托、Handoff、有限辩论和裁判策略。
- 每个节点定义输入、输出、Agent、工具、知识、预算、超时、重试和失败策略。
- Handoff 明确控制权是否返回，并过滤传递上下文。
- 工作流发布前检查依赖、Schema、权限、终止条件和预算。
- 平台可以生成草案，但发布前必须由用户确认。

### 6.8 Live Arena 与运行控制

- 运行真实、隔离的 Agent Instance。
- 支持启动、暂停、恢复、停止、取消、重试和检查点恢复。
- 实时展示任务图、Agent 状态、消息、Handoff、工具、知识、产物和质量门。
- 用户可以回答 Agent 问题、批准动作、修改限制或接管任务。
- 记录模型、Prompt、Agent、工作流、工具和知识版本。
- 支持同步、异步、流式和长任务。

### 6.9 Artifact、Evidence 与报告

- 正式产物独立于聊天消息保存并版本化。
- 每个结论可以关联证据、来源、Agent 和生成步骤。
- 缺陷包含目标产物、严重度、证据、复现、建议和状态。
- 修订必须引用被修复缺陷并产生新 Artifact Version。
- 裁判输出评分、理由、证据、通过/返工/阻断决定。
- 最终报告整合产物、证据、缺陷、修订、决策、成本和时间。

### 6.10 Evaluation Lab 与持续学习

- 测试预期路由 Agent、工具调用、知识检索、结果和安全行为。
- 支持确定性断言、语义评分、裁判模型、人工评分和基准答案。
- 比较单 Agent、多 Agent 协作、多 Agent 对抗和不同版本。
- 统计质量、证据覆盖、缺陷发现/修复、成本、时延、稳定性和人工工作量。
- 支持测试集版本、批量运行、A/B 实验和回归门禁。
- 只有经过审核的配置和经验才能进入模板库与方法库。

## 7. 首批协作与对抗能力

| 能力 | 首版要求 |
| --- | --- |
| 路由 | 规则路由和模型路由，记录选择理由与置信度 |
| 委托 | 父子任务、结构化任务契约、并行执行和结果汇总 |
| Handoff | 类型化载荷、上下文过滤、控制权和责任转移 |
| 协作 | 串行交接、并行专家、共享 Artifact |
| 对抗 | 提案、挑战、回应、修订、复测 |
| 裁判 | 规则检查 + 量表 + 证据 + 可选裁判模型 |
| 人工介入 | 输入、批准、否决、修改、接管 |
| 终止 | 成功、失败、阻断、取消、预算耗尽、超时分别处理 |

Swarm 和大规模社会模拟不是首版运行方式，但应保留事件环境和社会模板扩展能力。

## 8. 非功能需求

### 8.1 安全

- 最小权限、Workspace 隔离和服务端强制鉴权。
- MCP/A2A Endpoint、模型和工具凭据安全管理。
- 提示注入、数据泄露、越权调用和记忆污染防护。
- 敏感字段脱敏，禁止保存私有思维链。
- 高风险动作有审批、撤销或补偿机制。

### 8.2 可靠性

- 事件、任务和 Artifact 幂等。
- 状态可持久化、恢复和回放。
- 超时、预算耗尽和人为停止不会被标记为成功。
- 循环必须有退出条件。
- 正式产物不可原地覆盖。

### 8.3 可观察性

- 使用统一 Trace ID 串联场景、工作流、任务、Agent、工具和产物。
- 展示 Token、费用、时延、错误、重试和人工等待。
- 支持 OpenTelemetry 兼容导出。
- 支持按 Agent、版本、场景和工作流聚合分析。

### 8.4 开放性

- 模型、向量库、检索后端和对象存储可替换。
- 工具兼容 MCP，外部 Agent 逐步兼容 A2A。
- 领域对象和声明式 Schema 版本化。
- API-first，Client 不拥有核心业务逻辑。

### 8.5 易用性

- 首屏是可工作的 Workspace 控制台，而非固定 Demo。
- 非技术用户可用向导和模板完成场景创建。
- 专业用户可进入详细配置和声明式编辑。
- 运行视图优先展示任务、产物和风险，不以聊天流为唯一中心。

## 9. 优先级与发布边界

### 9.1 P0：可配置、真实运行、可验证

1. Workspace 与基础资源隔离。
2. Scenario Builder。
3. Agent Registry 基础 CRUD、测试和版本。
4. Knowledge Hub 文件接入与带来源检索。
5. Tool Registry 基础工具与 MCP 接口。
6. Workflow Studio 的确定性节点、委托和有限辩论。
7. 真实模型运行、状态持久化和人工介入。
8. Artifact、Evidence、Defect、Decision 数据模型。
9. Live Arena 实时观察。
10. Evaluation Lab 的单 Agent/多 Agent 对比。

### 9.2 P1：平台化和开放生态

- Society Designer 完整关系和政策。
- 自动推荐 Agent 团队与工作流草案。
- Agent/Workflow 声明式导入导出。
- A2A Agent 登记与调用。
- 检查点恢复、A/B Run 和回归测试。
- 多 Workspace 成员角色和审批。
- 模板库与经过审核的经验写回。

### 9.3 P2：学习型 Agent 社会

- Agent 能力画像和声誉。
- 工作流自动优化建议。
- 多方案竞赛、委员会和市场机制。
- 大规模异步 Agent 社会模拟。
- 组织级 Agent 资产市场和跨 Workspace 共享。

## 10. 建议成功指标

以下是首版建议目标，需用户确认，不视为既定承诺：

| 指标 | 建议目标 |
| --- | --- |
| 自定义场景创建 | 无需修改代码即可完成 |
| 可追溯率 | 关键结论 95% 以上可跳转到证据或产物 |
| 运行控制 | 100% 运行可停止，停止状态准确 |
| 版本复现 | 每次运行保存全部关键版本和参数 |
| 多 Agent 价值 | 至少一个验收案例在质量或风险发现上优于单 Agent |
| 评测完整性 | 路由、工具、知识、结果、安全、成本和时延均有指标 |
| 模板复用 | 新场景可以从已验证模板复制并修改 |

## 11. 仍需后续确认

1. 首版模型供应商与单次运行成本上限。
2. 首批知识来源及是否需要完全离线部署。
3. 第一批真实工具和必须审批的操作。
4. 首版单用户还是多人 Workspace。
5. 自动生成 Agent/Workflow 的允许程度。
6. 首版是否立即实现 A2A，还是先保持兼容数据模型。
