- 版本：1.0
- 日期：2026-07-24
- 状态：待用户确认

## 1. 文档目的

本文档回答：

1. 用户真正想解决什么问题。
2. Agent Arena 面向哪些用户。
3. 用户需要完成哪些关键任务。
4. 平台必须具备哪些功能和质量属性。
5. 课题版本、平台第一版和长期版本如何划分。
6. 哪些需求已经确认，哪些仍需用户决策。

本文档确认后，作为后续 PRD、架构、迭代计划和验收测试的需求基线。

## 3. 用户核心问题

### 3.1 当前问题

- 现有 Demo 固定为“智能需求评审示例”，不能创建其他场景。
- Agent 固定写在代码中，用户不能配置。
- 当前协作与对抗由固定事件模拟，不是真实 LLM Agent。
- 没有用户自己的知识库和知识权限体系。
- 没有可复用的 Agent 组织、社会规则和工作流模板。
- 无法验证多 Agent 是否真的比单 Agent 效果更好。

### 3.2 用户期望

用户希望拥有自己的多 Agent 平台：

> 在员工、研发、客户、运营等场景下，输入业务目标和资料，平台能够帮助构建、运行和评估对应的多 Agent 协作与对抗工作流。

## 4. 产品目标层级

### 4.1 课题目标

- 选择一个真实生产流。
- 至少设计 3 个不同角色的 Agent。
- 明确职责、工具、信息传递和依赖。
- 包含协作和对抗环节。
- 系统可以真实运行和演示。
- 提供角色说明、流程图、README 和完整示例。
- 比较单 Agent 与多 Agent 的效果。

状态：**已确认**

课题目标是平台的一个验收条件，不是产品规划的主轴。平台不应围绕某个课题案例进行硬编码。

### 4.2 平台第一目标

- 用户能够创建场景，而不是只能运行固定 Demo。
- 用户能够新增和配置 Agent。
- 用户能够连接自己的知识。
- 用户能够设计或生成工作流。
- 至少四个真实 Agent 能完成协作、红队、修订和裁判闭环。
- 用户能够实时观察、干预和复盘。

状态：**已确认 + 推导**

该目标优先于具体课题案例选择。

### 4.3 长期目标

- 平台拥有 Agent 蓝图库、社会体系和工作流工厂。
- 平台可以针对不同场景推荐 Agent 团队和协作/对抗模式。
- 平台能够复用经过验证的工作流模板。
- 平台能够基于历史运行数据优化 Agent 和流程。
- 平台能够覆盖员工、开发、客户和运营等场景族。

状态：**已确认**

## 5. 产品定位

Agent Arena 的产品定位：

> **面向组织场景的多 Agent 社会操作系统与工作流工厂。**

它不是：

- 单一需求评审工具
- Agent 聊天室
- 提示词管理器
- 单纯的流程画布
- 只有展示效果的模拟器

它需要同时管理：

- 场景
- 知识
- Agent
- 组织关系
- 社会制度
- 工作流
- 运行
- 产物
- 对抗
- 评估
- 经验沉淀

## 6. 目标用户

### 6.1 平台所有者

即当前主要用户。

需求：

- 建立自己的多 Agent 能力体系。
- 管理知识、Agent、工具、模板和运行记录。
- 将平台扩展到不同业务场景。
- 评估系统效果和成本。

优先级：**P0**

### 6.2 场景创建者

可能是产品经理、研发负责人、HR、客户成功、运营或业务专家。

需求：

- 用自然语言描述业务目标。
- 上传场景资料。
- 设置约束、风险和验收标准。
- 使用模板快速生成工作流。

优先级：**P0**

### 6.3 Agent/工作流设计者

需求：

- 新增和配置 Agent。
- 配置模型、提示词、工具、知识权限和预算。
- 设计 Agent 关系和工作流。
- 定义协作、对抗、返工和裁判规则。

优先级：**P0**

### 6.4 知识管理员

需求：

- 创建知识空间。
- 上传或连接知识来源。
- 设置权限、有效期和敏感级别。
- 审核运行经验是否写回。

优先级：**P1**

### 6.5 运行操作与观察者

需求：

- 启动、暂停、继续和停止运行。
- 实时查看 Agent 状态、消息、工具和产物。
- 回答 Agent 问题或批准高风险操作。

优先级：**P0**

### 6.6 审核与管理者

需求：

- 查看证据、缺陷、修订和评分。
- 处理风险豁免。
- 比较不同运行结果。
- 追溯责任和决策过程。

优先级：**P1**

## 7. 核心用户旅程

### 7.1 从零创建场景

```text
进入 Workspace
-> 新建 Scenario
-> 描述业务目标
-> 上传资料
-> 设置约束和验收标准
-> 保存场景
```

### 7.2 构建 Agent 社会

```text
平台分析场景
-> 推荐 Agent 团队
-> 用户新增/删除/编辑 Agent
-> 配置模型、工具、知识和预算
-> 配置协作、监督和裁判关系
-> 保存 Society Definition
```

### 7.3 生成和编辑工作流

```text
平台推荐工作流
-> 显示任务、依赖和产物
-> 显示协作和对抗节点
-> 显示人工确认点
-> 用户编辑
-> 静态校验
-> 发布 Workflow Definition
```

### 7.4 运行和人工介入

```text
选择场景、社会和工作流版本
-> 启动
-> 查看实时事件
-> 回答开放问题
-> 批准高风险工具
-> 暂停或调整预算
-> 继续或终止
```

### 7.5 审核和深度交互

```text
查看最终产物
-> 查看红队缺陷和修订
-> 查看裁判评分
-> 追溯证据
-> 采访任意 Agent
-> 向多个 Agent 发送问卷
```

### 7.6 评估与复用

```text
与单 Agent 基线对比
-> 比较质量、成本和时间
-> 查看 Agent 贡献
-> 保存有效配置为模板
-> 审核经验写回知识库
```

9. 实时运行和人工介入
10. 单 Agent 与多 Agent 对比

实现顺序必须以通用领域对象和配置能力为中心，不能先将某个需求开发案例写死，再逐步抽象。

## 11. 课题交付验收标准

课题案例仅用于验证通用平台。最终可从需求开发中选择一个具体需求，通过平台创建场景、配置 Agent、生成工作流并完成运行。

课题版本满足以下条件才算完成：

- [ ] 平台可以创建一个需求开发场景，而不是由代码预置场景。
- [ ] 至少 4 个真实 LLM Agent 独立执行。
- [ ] 每个 Agent 有明确职责、工具和输入输出。
- [ ] Agent 之间存在真实消息或产物交接。
- [ ] 至少发生一次结构化红队攻击。
- [ ] 修订 Agent 根据缺陷生成新版本。
- [ ] 红队对新版本复测。
- [ ] 裁判根据量表和证据评分。
- [ ] 用户可以观察和人工介入。
- [ ] 生成完整报告和审计记录。
- [ ] 完成单 Agent 与多 Agent 的质量、成本和时间对比。
- [ ] 提供流程图、角色说明、README 和演示步骤。

## 12. 平台第一版验收标准

- [ ] 首页不再固定加载 `/api/demo`。
- [ ] 用户可以创建 Workspace 和 Scenario。
- [ ] 用户可以新增、编辑、复制、启停 Agent。
- [ ] 用户可以给 Agent 配置模型、提示词、工具和知识权限。
- [ ] 用户可以保存和版本化工作流。
- [ ] 用户可以运行自己配置的场景。
- [ ] 页面显示真实 Agent 消息、产物和工具事件。
- [ ] 数据在服务重启后仍然存在。
- [ ] 不同 Workspace 之间数据隔离。
- [ ] 运行可以安全停止，且停止不显示为完成。

## 13. 近期明确不做

- 一开始支持所有行业。
- 数百或数千 Agent 的大规模仿真。
- 无人工确认地自动执行高风险生产操作。
- 完全自动且无需编辑的工作流生成。
- 只依据 LLM 自评决定工作流效果。
- 让一个 Agent 同时拥有提案、修改和最终审批权。

## 14. 待确认问题

### 14.1 业务优先级

已确认：

- 具体课题案例不是当前重点。
- 最终从需求开发中选择一个具体需求即可。
- 当前重点是通用平台能力。

### 14.2 模型和成本

1. 首版使用哪家模型服务？
2. 是否需要同时支持多个模型供应商？
3. 单次运行可以接受的费用和等待时间是多少？

### 14.3 知识与安全

4. 第一批知识来自本地文件、数据库、Git 仓库还是企业系统？
5. 是否包含敏感、个人或客户数据？
6. 是否要求完全本地或离线部署？

### 14.4 工具和外部系统

7. 第一版 Agent 需要调用哪些真实工具？
8. 是否需要接入 GitHub、企业 IM、工单、CRM 或内部系统？
9. 哪些操作必须人工审批？

### 14.5 工作流生成

10. 用户希望首版以模板配置为主，还是自动生成为主？
11. 自动生成的 Agent 和工作流是否必须由用户逐项确认？

### 14.6 用户和权限

12. 第一版是单用户使用还是多人协作？
13. 是否需要登录、角色和组织权限？

## 15. 推荐的需求确认顺序

为了避免同时讨论所有问题，建议按以下顺序确认：

1. 第一版 Workspace、Scenario、Agent Blueprint 和 Workflow Definition 的边界。
2. 第一版模型供应商与费用预算。
3. 第一批知识来源和数据安全要求。
4. Agent 配置项和真实工具。
5. 工作流以模板为主还是自动生成优先。
6. 单用户还是多人 Workspace。

课题案例选择推迟到平台已经可以创建和运行自定义场景之后。
